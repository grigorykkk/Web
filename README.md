## Цель работы

Целью контрольной работы №2 было объединить результаты выполненных практических занятий в одно полноценное веб-приложение с серверной и клиентской частью.  
В ходе работы нужно было реализовать регистрацию и авторизацию пользователей, защиту маршрутов, работу с JWT и refresh-токенами, клиентскую часть на React, а также разграничение прав доступа по ролям.

## Общая характеристика проекта

Итоговый проект представляет собой приложение, состоящее из двух частей:

- **backend** — серверная часть на Node.js и Express;
- **frontend** — клиентская часть на React.

Приложение позволяет пользователям регистрироваться, входить в систему, получать информацию о себе, работать с товарами, а также выполнять действия в зависимости от своей роли в системе.

## Ход выполнения работы

### 1. Реализация базовой аутентификации ПРАКТИЧЕСКАЯ 7

На начальном этапе была создана серверная часть приложения.  
Была реализована регистрация пользователей и вход в систему. Для хранения паролей использовалось хеширование, чтобы не сохранять пароли в открытом виде.

Также были добавлены основные CRUD-операции для работы с товарами: создание, просмотр, изменение и удаление.

В результате этого этапа приложение уже позволяло:

- зарегистрировать пользователя;
- выполнить вход;
- хранить пароль в безопасном виде;
- выполнять базовые операции с товарами.

### 2. Реализация JWT-аутентификации ПРАКТИЧЕСКАЯ 8

Далее в проект была добавлена аутентификация с использованием JWT.  
После успешного входа пользователь получает токен, который затем используется для доступа к защищенным маршрутам.

Дополнительно был реализован маршрут для получения данных текущего пользователя.  
Это позволило организовать работу авторизации уже в более современном и удобном формате.

На этом этапе были решены следующие задачи:

- выдача access token после входа;
- проверка токена на защищенных маршрутах;
- получение информации о текущем пользователе;
- ограничение доступа для неавторизованных пользователей.

### 3. Добавление refresh-токенов ПРАКТИЧЕСКАЯ 9

Следующим шагом была реализована поддержка refresh-токенов.  
Это нужно для того, чтобы пользователь мог продолжать работу в системе без повторного ввода логина и пароля после истечения access token.

В приложении был создан отдельный маршрут для обновления токенов.  
При обращении к нему старый refresh-токен заменяется новым, а пользователь получает новую пару токенов.

Таким образом, в системе появилась более удобная и безопасная схема авторизации.

### 4. Разработка клиентской части на React ПРАКТИЧЕСКАЯ 10

После завершения основной логики backend была создана клиентская часть приложения на React.  
Интерфейс позволяет взаимодействовать с сервером через формы и кнопки, а не только через API-запросы.

Во frontend были реализованы:

- форма регистрации;
- форма входа;
- отображение информации о текущем пользователе;
- просмотр списка товаров;
- получение товара по идентификатору;
- создание нового товара;
- редактирование товара;
- удаление товара;
- обработка ошибок при выполнении запросов.

Также была реализована автоматическая попытка обновления access-токена через refresh-токен, если сервер возвращает ошибку авторизации.

### 5. Реализация ролевой модели доступа ПРАКТИЧЕСКАЯ 11

На завершающем этапе была добавлена ролевая модель RBAC.  
В системе используются несколько ролей:

- **user** — обычный пользователь;
- **seller** — продавец;
- **admin** — администратор.

Для каждой роли были определены свои права доступа.

#### Права ролей:

- **Пользователь** может просматривать товары и получать информацию о себе.
- **Продавец** может создавать и редактировать товары.
- **Администратор** может управлять товарами и пользователями.
